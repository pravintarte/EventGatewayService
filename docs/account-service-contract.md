# Event Gateway to Account Service Contract

This document describes the HTTP contract that Event Gateway consumes from
Account Service. The executable version of this contract is generated by
`AccountServicePactConsumerTest` as a Pact file:

```text
target/pacts/event-gateway-api-account-service.json
```

## Pacticipants

- Consumer: `event-gateway-api`
- Provider: `account-service`

## Shared Headers

Event Gateway sends these headers on every Account Service request:

| Header | Value | Purpose |
| --- | --- | --- |
| `X-Internal-Caller` | `event-gateway-api` | Identifies Event Gateway as the internal caller. |
| `X-Internal-Token` | `local-dev-token` by default | POC shared-token guard for local/internal calls. |
| `X-Trace-Id` | current request trace id | Correlates Gateway logs with Account Service logs for one client request. |

Transaction apply calls also send:

| Header | Value | Purpose |
| --- | --- | --- |
| `Idempotency-Key` | upstream `eventId` | Lets Account Service deduplicate gateway retries. |

Production should replace the POC shared-token guard with network policy,
mTLS, OAuth2 client credentials, or service mesh identity.

## Apply Transaction

```http
POST /accounts/{accountId}/transactions
Content-Type: application/json
Idempotency-Key: {eventId}
X-Internal-Caller: event-gateway-api
X-Internal-Token: local-dev-token
```

Request body:

```json
{
  "eventId": "9b63f0d4-0f49-4f85-9447-fd45a0c5b3c2",
  "type": "CREDIT",
  "amount": 150.00,
  "currency": "USD",
  "eventTimestamp": "2026-05-15T14:02:11Z",
  "metadata": {
    "source": "pact-consumer-test"
  }
}
```

Provider response semantics:

| Status | Meaning in Event Gateway |
| --- | --- |
| `2xx` | Transaction applied successfully. Gateway marks event `APPLIED`. |
| `4xx` | Non-retryable rejection. Gateway marks event `APPLY_REJECTED`. |
| `5xx`, timeout, connection failure | Retryable downstream failure. Gateway marks event `APPLY_FAILED` and retries later. |

The Pact consumer test currently covers `204 No Content` success and
`409 Conflict` rejection.

## Read Balance

```http
GET /accounts/{accountId}/balance
Accept: application/json
X-Internal-Caller: event-gateway-api
X-Internal-Token: local-dev-token
```

Account Service response body and status are proxied back to the external
caller by Event Gateway. If Account Service cannot be reached, Event Gateway
returns its own `503 ACCOUNT_SERVICE_UNAVAILABLE` fallback response.

## Read Account

```http
GET /accounts/{accountId}
Accept: application/json
X-Internal-Caller: event-gateway-api
X-Internal-Token: local-dev-token
```

Account Service response body and status are proxied back to the external
caller by Event Gateway. The Pact consumer test currently covers `404 Not Found`
preservation.

## Running Consumer Contract Tests

Generate the local consumer pact:

```powershell
mvn "-Dtest=AccountServicePactConsumerTest" test
```

Run all tests including Pact consumer tests:

```powershell
mvn test
```

## Publishing to PactFlow

PactFlow supports the open-source Pact Broker workflow. Event Gateway generates
the consumer pact locally, then publishes it to PactFlow during CI.

Required environment variables:

```powershell
$env:PACT_BROKER_BASE_URL = "https://<your-org>.pactflow.io"
$env:PACT_BROKER_TOKEN = "<pactflow-token>"
$env:PACT_CONSUMER_BRANCH = "main"
```

Recommended CI command:

```powershell
mvn "-Dtest=AccountServicePactConsumerTest" test
mvn "-Dpacticipant.version=<git-sha-or-build-number>" pact:publish
```

The Account Service provider pipeline should retrieve this pact from PactFlow,
verify it against the running Account Service provider, and publish provider
verification results back to PactFlow before deployment.
